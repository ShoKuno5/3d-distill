# Architecture Survey: 3D Generation Models

# CAST

- Basic Information
  - Paper: "CAST: Component-Aligned 3D Scene Reconstruction from an RGB Image" (arXiv: 2502.12894)
  - Repo: https://github.com/FishWoWater/CAST (unofficial implementation by Junjie Wang)
  - Year: 2025
  - Organization: Original paper from multiple institutions; this unofficial repo is by FishWoWater (Junjie Wang)
  - Task framing: Component-aligned 3D scene reconstruction from a single RGB image -- detects objects, generates per-object 3D meshes, estimates 6D poses, assembles into a composed scene
  - Output type: Per-object textured 3D meshes (GLB/PLY/OBJ) with 6D poses, combined into a reconstructed scene (GLB)

- Input / Output
  - Inputs
    - Modalities: Single RGB image (JPG, PNG, BMP, TIFF)
    - Required preprocessing: RAM resizes to 384x384 for tagging; Grounding DINO uses RandomResize to 800 (max 1333); MoGe normalizes to [0,1] float32
    - Input resolution: No fixed requirement. RAM internally resizes to 384x384; Grounding DINO resizes to ~800px; MoGe processes at native resolution
    - Conditioning method: Not applicable (single-image input; no explicit conditioning signal)
  - Outputs
    - Representations: Per-object 3D meshes (vertices + faces), 6D pose per object (3x3 rotation, 3D translation, 3D scale), scene-level composed GLB/PLY, depth map, point cloud, scene graph
    - Texture / material support: Yes. Meshes include vertex/face colors. Tripo3D outputs PBR models. TRELLIS and Hunyuan3D output textured GLB.
    - Post-processing required: Scene graph optimization with SDF-based physical correctness (penetration/contact resolution) is partially implemented (marked "TO BE DONE")

- Core Architecture
  - Internal representation: Per-object point clouds from MoGe depth estimation using segmentation masks; per-object 3D meshes generated by external APIs; 6D poses optimized via chamfer distance
  - Backbone: No single backbone. Modular pipeline: RAM (Swin-L for tagging), Grounding DINO (SwinT for detection), SAM (ViT-H for segmentation), MoGe v2 (ViT-L for depth), CLIP (render-and-compare), Orient-Anything (rotation), Qwen-VL (filtering/captioning)
  - Latent / VAE
    - VAE present: No
    - Latent structure: Not applicable
    - What the VAE encodes: Not applicable
  - Pipeline structure
    - Stages: (1) Object detection (RAM + Grounding DINO), (1.5) Detection filtering (Qwen-VL + size filtering), (1.75) Segmentation (SAM), (2) Depth estimation (MoGe v2), (2.5) Image inpainting for occluded objects (Flux-Kontext via Replicate), (3) 3D mesh generation (Tripo3D / TRELLIS / Hunyuan3D), (4) Pose estimation (ICP or PyTorch chamfer optimization + OrientAnything), (5) Scene graph extraction and optimization
    - Key modules: DetectionSegmentationModule, DetectionFilteringModule, ImageGenerationModule, DepthEstimationModule, MeshGenerationModule, PoseEstimationModule (PyTorchPoseOptimizer), RenderCompareModule, SceneGraphOptimizationModule

- Multiview Support
  - Native multiview support: No. Single-image input only.
  - Multi-view aggregation: Not applicable
  - View count supported: 1
  - View consistency mechanism: Not applicable. Render-and-compare evaluates mesh from multiple viewpoints for pose estimation, but this is not multi-view input.

- Training Setup
  - Training datasets: None. Training-free pipeline using pretrained models and external APIs.
  - Dataset scale: Not applicable
  - Supervision signals: Not applicable
  - Losses: Pose optimization: bidirectional chamfer distance (L1) with optional normal loss and rotation regularization. Scene graph optimization: penetration loss (SDF-based), contact loss, support loss, gravity loss.
  - Training code available: No (no training involved)

- Evaluation Protocol
  - Benchmarks used: Unknown
  - Metrics reported: Unknown
  - Human evaluation: Unknown
  - Efficiency metrics: Unknown

- Accessibility
  - Weights available: Uses publicly available pretrained weights (SAM, Grounding DINO, RAM, MoGe v2). No custom-trained weights.
  - Inference code available: Yes (full pipeline via `python -m cast.cli`)
  - Training code available: No (training-free approach)
  - License: MIT

- Efficiency
  - Typical inference runtime: Unknown (involves multiple external API calls with timeouts up to 10 minutes per mesh)
  - GPU memory: 12GB VRAM or more required (stated in README)
  - Sampling steps: Not applicable (no diffusion in core pipeline; external APIs handle generation)

- Strengths
  - Fully modular pipeline where each component can be independently upgraded
  - Training-free: no custom model training required
  - Handles object occlusion via inpainting before mesh generation
  - Supports multiple mesh generation backends (Tripo3D, TRELLIS, Hunyuan3D)
  - Differentiable pose optimization with 6D rotation representation and chamfer loss
  - Resume capability from intermediate checkpoints

- Limitations
  - Explicitly described as "proof-of-concept and work-in-progress" by the author
  - Performance not expected to approach the original paper (lacks occlusion-aware generative model)
  - Depends heavily on external paid APIs (Replicate, Tripo3D, DashScope/Qwen)
  - Scene graph SDF-based optimization marked "TO BE DONE"
  - No formal evaluation or benchmarks
  - Single-image only; no multi-view support

- Distillation Suitability
  - Teacher quality potential: Low-Medium. Author states results have "obvious artifacts" and do not approach original paper quality.
  - Multi-view compatibility: Low. Single-image input only.
  - Latent accessibility: Low. No latent space or VAE. Procedural pipeline stitching external API calls.
  - Reproducibility: Low-Medium. Depends on paid external APIs whose availability may change. Local components (RAM, SAM, MoGe) are reproducible.
  - Overall suitability score (1-5): 2

# Hunyuan3D

- Basic Information
  - Paper: "Hunyuan3D 2.0: Scaling Diffusion Models for High Resolution Textured 3D Assets Generation" (arXiv:2501.12202); also "Hunyuan3D 2.5" (arXiv:2506.16504)
  - Repo: https://github.com/Tencent/Hunyuan3D-2
  - Year: 2025
  - Organization: Tencent (Hunyuan3D Team)
  - Task framing: Image-to-3D (single image or multiview to textured 3D mesh); text-to-3D via HunyuanDiT front-end
  - Output type: Textured 3D mesh (trimesh/GLB/OBJ)

- Input / Output
  - Inputs
    - Modalities: Single image (RGBA/RGB) or multiview images (front, left, back, right); optionally text (via text-to-image front-end)
    - Required preprocessing: Background removal (rembg), recenter/rescale with border ratio (~0.15-0.2), resize to 512x512, normalize to [-1,1]. Conditioner images resized to 224x224 for DINOv2/CLIP with ImageNet normalization.
    - Input resolution: 512x512 for image processor; 224x224 for DINOv2/CLIP conditioner
    - Conditioning method: DINOv2 (main) and/or CLIP vision features projected via linear layer into DiT hidden dimension, used as cross-attention tokens in double-stream attention blocks
  - Outputs
    - Representations: 3D mesh (vertices + faces) from occupancy field via marching cubes or differentiable marching cubes (DiffDMC), decoded from latent tokens via cross-attention volume decoder
    - Texture / material support: Yes. Hunyuan3D-Paint generates texture maps (2048x2048) via multiview diffusion and back-projection/baking onto UV-mapped meshes.
    - Post-processing required: Marching cubes extraction, UV unwrapping (xatlas), texture baking from multiview renders, texture inpainting for uncovered regions

- Core Architecture
  - Internal representation: Latent vector set ("vectset") -- a set of latent tokens of shape (num_latents, embed_dim)
  - Backbone: Two alternatives: (1) Hunyuan3DDiT -- FLUX-style flow-matching DiT with double-stream + single-stream blocks, AdaLN modulation. (2) HunYuanDiTPlain -- U-shaped DiT with skip connections, optional MoE FFN. Texture model: UNet2p5DConditionModel with multiview + reference attention.
  - Latent / VAE
    - VAE present: Yes. ShapeVAE (VectsetVAE) with PointCrossAttentionEncoder + KL bottleneck + Transformer decoder + CrossAttentionDecoder
    - Latent structure: Set of tokens (num_latents, embed_dim). Encoder uses FPS to downsample point clouds, cross-attention to create latents, KL bottleneck (DiagonalGaussianDistribution).
    - What the VAE encodes: Surface point clouds with features (points + normals). Encoder takes point coordinates (Fourier embedding) and features (normals), downsamples via FPS, encodes via cross-attention and self-attention.
  - Pipeline structure
    - Stages: (1) Shape generation -- image conditioning -> DiT diffusion in latent vectset space -> VAE decode to occupancy -> marching cubes. (2) Texture synthesis -- mesh rendering (normals, positions) -> delight input -> multiview diffusion (UNet2.5D) -> back-project and bake texture -> UV inpaint.
    - Key modules: ImageProcessorV2, DINOv2/CLIP conditioners, Hunyuan3DDiT/HunYuanDiTPlain, FlowMatchEulerDiscreteScheduler, ShapeVAE, VolumeDecoder (Vanilla/FlashVDM/Hierarchical), MCSurfaceExtractor/DMCSurfaceExtractor, Light_Shadow_Remover, Multiview_Diffusion_Net, UNet2p5DConditionModel

- Multiview Support
  - Native multiview support: Yes. Hunyuan3D-2mv variant accepts multiview images for shape generation. Texture pipeline generates multiview renders internally.
  - Multi-view aggregation: Shape (2mv): DinoImageEncoderMV concatenates per-view DINOv2 features with sinusoidal view embeddings. Texture: multiview attention + reference attention in Basic2p5DTransformerBlock.
  - View count supported: Shape (2mv): up to 4 views (front, left, back, right). Texture: 6 canonical views (4 azimuths at elev 0, plus elev +90/-90).
  - View consistency mechanism: UNet2p5DConditionModel uses multiview self-attention, reference attention from dual-stream reference encoding, camera embeddings, and optional voxel-grid position-aware attention masks.

- Training Setup
  - Training datasets: Unknown (not disclosed in this codebase)
  - Dataset scale: Unknown
  - Supervision signals: Unknown (training code not in this repo; mentioned for Hunyuan3D-2.1)
  - Losses: VAE has KL divergence + NLL. MoE layers have auxiliary load-balancing loss. Specific DiT/texture training losses not present.
  - Training code available: No (directed to Hunyuan3D-2.1 repo)

- Evaluation Protocol
  - Benchmarks used: Unknown
  - Metrics reported: CMMD, FID_CLIP, FID, CLIP-score (from README performance table)
  - Human evaluation: Unknown
  - Efficiency metrics: Unknown

- Accessibility
  - Weights available: Yes. Multiple variants on HuggingFace: DiT-v2-0 (1.1B), DiT-v2-0-Fast (1.1B), DiT-v2-0-Turbo (1.1B), DiT-v2-mv (1.1B), DiT-v2-mini (0.6B), DiT-v2-1 (3.0B), Paint-v2-0 (1.3B), Paint-v2-1 (1.3B), Delight-v2-0 (1.3B).
  - Inference code available: Yes
  - Training code available: No (in this repo; available in Hunyuan3D-2.1 separate repo)
  - License: Tencent Hunyuan 3D 2.0 Community License -- non-commercial; commercial use requires Tencent license for >1M MAU. Excludes EU, UK, South Korea.

- Efficiency
  - Typical inference runtime: Unknown. Default shape generation uses 50 diffusion steps; turbo/fast variants use fewer.
  - GPU memory: 6 GB VRAM for shape only; 16-24.5 GB for shape + texture
  - Sampling steps: Default 50 steps for flow matching; turbo/fast variants fewer. Texture: default 28 steps; turbo uses 10 steps.

- Strengths
  - Comprehensive two-stage pipeline cleanly decoupling shape and texture
  - Multiple model sizes (0.6B-3.0B) with distilled turbo/fast variants
  - Native multiview input (Hunyuan3D-2mv) for improved shape fidelity
  - High-resolution texture generation (2048x2048) with multiview consistency
  - FlashVDM accelerated volume decoding for faster mesh extraction
  - Flexible latent vectset representation enables VAE encode/decode of arbitrary meshes
  - Multiple interfaces: Python API, Gradio, REST API, Blender addon, ComfyUI

- Limitations
  - Training code and data not available in this repo
  - License restricts commercial use and excludes EU/UK/South Korea
  - **License Section 5(b) explicitly prohibits using outputs to improve non-Hunyuan AI models (blocks distillation)**
  - Texture baking relies on fixed canonical camera views
  - Point cloud VAE encoder requires torch_cluster FPS dependency

- Distillation Suitability
  - Teacher quality potential: High -- SOTA results on multiple metrics; multiple model sizes and quality tiers
  - Multi-view compatibility: High -- native multiview input (2mv) and multiview texture generation
  - Latent accessibility: High -- vectset latent space explicitly accessible; VAE encode/decode are separate calls
  - Reproducibility: Medium-High -- inference code and weights available; training code in separate repo; no dataset access
  - Overall suitability score (1-5): 3 (excellent architecture but license Section 5b is a hard legal blocker for distillation into non-Hunyuan models)

# SAM-3D-Objects

- Basic Information
  - Paper: "SAM 3D: 3Dfy Anything in Images" (arXiv:2511.16624)
  - Repo: https://github.com/facebookresearch/sam-3d-objects
  - Year: 2025
  - Organization: Meta Superintelligence Labs
  - Task framing: Single-image 3D object reconstruction (geometry, texture, and layout from a single image with object masks)
  - Output type: 3D Gaussian splats (.ply), meshes (.glb), and 6DoF pose (rotation, translation, scale)

- Input / Output
  - Inputs
    - Modalities: Single RGB image + binary object mask (RGBA); optionally a point map from MoGe monocular depth
    - Required preprocessing: Image resized/cropped via configurable PreProcessor; mask binarized as alpha channel; MoGe produces point maps converted to PyTorch3D convention
    - Input resolution: 512x512 (warmup); DINOv2 resizes to 224x224; PointPatchEmbed uses configurable input_size (default 256)
    - Conditioning method: DINOv2 image features + optional PointPatchEmbed point map features, fused via EmbedderFuser (concatenation with learned positional embeddings); fed as cross-attention to DiT blocks; classifier-free guidance with PointmapCFG variant
  - Outputs
    - Representations: 3D Gaussian splats (xyz, color, scaling, rotation, opacity); meshes via FlexiCubes from sparse features; GLB with optional texture baking; 6DoF object pose
    - Texture / material support: Yes -- Gaussian splat color (SH degree 0), vertex colors on mesh, optional texture baking (1024x1024)
    - Post-processing required: Mesh simplification (95% triangle reduction), optional texture baking, optional ICP-based layout post-optimization

- Core Architecture
  - Internal representation: Structured Latent (SLaT) -- sparse 3D voxel grid with latent features per occupied voxel; Sparse Structure is binary occupancy at 64^3 encoded to 16^3 latent cube (8 channels)
  - Backbone: Two DiT models: (1) SparseStructureFlowModel (dense transformer with ModulatedTransformerCrossBlocks) for structure, (2) SLatFlowModel (sparse transformer with SparseResBlock3d U-Net IO blocks) for latent features; MOT variant supports multi-output-token predictions (shape + pose)
  - Latent / VAE
    - VAE present: Yes
    - Latent structure: Two-level: (1) SS VAE -- 64^3 binary occupancy to 16^3 x 8-channel latent (3D Conv ResBlocks); (2) SLat VAE -- per-voxel features to 8-channel latent per voxel (sparse transformer encoder), decoded by SLatGaussianDecoder or SLatMeshDecoder (FlexiCubes)
    - What the VAE encodes: (1) SS VAE: 3D occupancy structure. (2) SLat VAE: per-voxel appearance/geometry features decoded to Gaussian splat params or mesh SDF+color
  - Pipeline structure
    - Stages: (1) Generate sparse structure latent via flow matching DiT -> decode to binary occupancy -> extract voxel coordinates and pose. (2) Generate structured latent features at occupied voxels via sparse flow matching DiT -> decode to Gaussians and/or meshes.
    - Key modules: DINOv2 (frozen conditioner), PointPatchEmbed, EmbedderFuser, FlowMatching (Euler ODE), ShortCut (distillation-ready variant), SparseStructureEncoder/Decoder, SLatEncoder, SLatGaussianDecoder, SLatMeshDecoder (FlexiCubes), MoGe, PoseTargetConverter

- Multiview Support
  - Native multiview support: No -- single image input
  - Multi-view aggregation: Not applicable; multi-object scene assembly via per-object pose composition
  - View count supported: 1
  - View consistency mechanism: Not applicable; layout consistency via point map conditioning and ICP post-optimization

- Training Setup
  - Training datasets: Unknown (paper mentions "progressive training and a data engine with human feedback" but no dataset names in code)
  - Dataset scale: Unknown
  - Supervision signals: Unknown (no training code included)
  - Losses: Flow matching MSE loss; ShortCut self-consistency loss for distillation; VAE KL divergence
  - Training code available: No (loss functions defined but no training scripts/loops)

- Evaluation Protocol
  - Benchmarks used: Unknown (README mentions "a new challenging benchmark" but no eval code present)
  - Metrics reported: Unknown
  - Human evaluation: Mentioned in README ("outperforms prior models in human preference tests") but no eval code
  - Efficiency metrics: Unknown

- Accessibility
  - Weights available: Yes -- HuggingFace at `facebook/sam-3d-objects` (gated access, requires approval)
  - Inference code available: Yes -- `demo.py`, notebooks for single/multi-object and mesh alignment
  - Training code available: No (architecture and losses defined, but no training scripts)
  - License: SAM License (Meta custom -- non-exclusive, worldwide, royalty-free; allows derivatives; no ITAR/military use)

- Efficiency
  - Typical inference runtime: Unknown (default 25 steps per stage)
  - GPU memory: At least 32 GB VRAM required (stated in setup docs)
  - Sampling steps: 25 steps for sparse structure + 25 steps for structured latent (configurable); ShortCut supports fewer steps

- Strengths
  - Handles real-world scenes with occlusion, clutter, small objects, unusual poses
  - Produces 3D shape, texture, AND scene layout (6DoF pose) from a single image
  - Dual output: Gaussian splats for rendering + meshes via FlexiCubes
  - Point map conditioning enables metrically consistent layout
  - Built-in ShortCut distillation support for faster inference
  - ICP-based post-optimization refines poses

- Limitations
  - Single-view only -- no native multi-view support
  - High GPU memory (32+ GB VRAM)
  - No training code released
  - Gated checkpoint access (requires HuggingFace approval)
  - Depends on external models (DINOv2, MoGe)

- Distillation Suitability
  - Teacher quality potential: High -- detailed 3D geometry, texture, and layout; strong DiT + flow matching architecture
  - Multi-view compatibility: Low -- single-view only, though Gaussians can be rendered from any viewpoint
  - Latent accessibility: High -- two-level latent structure well-defined and accessible; normalization constants provided; clean separation of latent generation and decoding
  - Reproducibility: Medium -- inference code and weights (gated) available; no training code; architecture fully defined
  - Overall suitability score (1-5): 3

# Shaper

- Basic Information
  - Paper: "ShapeR: Robust Conditional 3D Shape Generation from Casual Captures" (arXiv: 2601.11514)
  - Repo: https://github.com/facebookresearch/ShapeR
  - Year: 2026
  - Organization: Meta Platforms, Inc.
  - Task framing: Metric 3D shape generation from casual captures (image sequences with SLAM data); object-centric reconstruction composable for scene-level results
  - Output type: 3D triangle mesh (.glb)

- Input / Output
  - Inputs
    - Modalities: Multi-view images (SLAM grayscale or RGB from Aria glasses), sparse 3D point cloud (from SLAM), camera extrinsics/intrinsics (FISHEYE624), text captions, 2D object projections, detection bounding boxes/masks
    - Required preprocessing: Aria MPS pipeline, 3D object instance detection, fisheye rectification, point cloud filtering by quality thresholds, normalization to [-0.9, 0.9], view selection (k-means/view angle/last_n), image cropping around object bbox
    - Input resolution: Configurable via patchified_grid_size * 14 (e.g., 448x448 for grid size 32). SLAM images are 480x640 (Gen1) or 512x512 (Gen2).
    - Conditioning method: Multi-modal via dual-stream transformer -- point cloud features (sparse 3D convolutions via torchsparse), image features (frozen DINOv2 + Plucker ray + mask injection), text features (T5-v1.1-XL + CLIP ViT-L). CLIP vector added to timestep embedding; T5 tokens attend via pre-text-attention or concatenation. All modalities concatenated with learned separator tokens. Classifier-free guidance with per-modality drop probabilities (point=0.2, image=0.35, text=0.45).
  - Outputs
    - Representations: 3D triangle mesh (trimesh.Trimesh) via marching cubes from UDF at 128^3 or octree depth 256, simplified to 125k faces
    - Texture / material support: No -- geometry only (vertex colors for visualization only)
    - Post-processing required: Floating geometry removal (>=5% faces of largest component), quadric decimation to 125k faces, optional world coordinate transform

- Core Architecture
  - Internal representation: VecSet latents -- set of latent tokens (batch, num_tokens, embed_dim), variable count based on FPS downsampling scales and token_multiplier (2 or 4)
  - Backbone: Frozen DINOv2 (ViT-L/14 with registers) for images, sparse 3D ResNet (torchsparse) for point clouds, T5-v1.1-XL + CLIP ViT-L for text
  - Latent / VAE
    - VAE present: Yes -- Michelangelo-like 3D VAE (inspired by DORA-VAE / Seed3D/Dora)
    - Latent structure: Variable-length token set (VecSet) with DiagonalGaussianDistribution (mean + logvar, KL-regularized). Token counts from FPS downsampling ratios.
    - What the VAE encodes: Surface point clouds (coarse + sharp) via Perceiver-style cross-attention encoder with FPS downsampling. Decoded by querying 3D positions against latents for occupancy/UDF.
  - Pipeline structure
    - Stages: (1) Preprocessing: fisheye rectification, view selection, point cloud filtering. (2) Feature extraction: DINOv2+Plucker rays, sparse 3D convolutions, T5+CLIP. (3) Flow matching: rectified flow on VecSet latent space using dual-stream transformer (Flux-style), midpoint ODE solver. (4) VAE decoding: latent tokens to 3D occupancy/UDF. (5) Mesh extraction: marching cubes. (6) Post-processing: floating geometry removal, simplification.
    - Key modules: ShapeRDenoiser, FlowMatchingTransformer (DoubleStreamBlocks + SingleStreamBlocks), MichelangeloLikeAutoencoder, DinoAndRayFeatureExtractor, PointCloudEncoder, TextFeatureExtractor, ODESolver, AffineProbPath + CondOTScheduler

- Multiview Support
  - Native multiview support: Yes -- fundamentally multi-view, designed for casual image sequences
  - Multi-view aggregation: Per-view DINOv2 features (with Plucker ray + mask embeddings) extracted independently, concatenated into single token sequence for cross-attention in dual-stream transformer. Training subsamples to 1024/V tokens per view.
  - View count supported: Configurable; presets are 4 views (speed) or 16 views (quality/balance)
  - View consistency mechanism: Camera-aware conditioning via Plucker ray coordinates per patch injected into DINOv2 features. Point cloud provides shared 3D context. Dual-stream transformer jointly attends over all view tokens. No explicit epipolar or consistency loss.

- Training Setup
  - Training datasets: Aria Gen1 simulated images (per notebook comment). Evaluation: ShapeR-Evaluation dataset on HuggingFace (facebook/ShapeR-Evaluation) from Aria glasses captures.
  - Dataset scale: Unknown
  - Supervision signals: Flow matching velocity prediction (MSE). VAE: reconstruction loss (occupancy/UDF) + KL divergence.
  - Losses: Flow matching MSE on velocity field. VAE: reconstruction + KL. Specific weights not in codebase.
  - Training code available: No -- inference only. Flow matching path utilities and training-time sampling code present but no training loop.

- Evaluation Protocol
  - Benchmarks used: ShapeR-Evaluation dataset on HuggingFace (facebook/ShapeR-Evaluation)
  - Metrics reported: Unknown (no evaluation scripts)
  - Human evaluation: Unknown
  - Efficiency metrics: Unknown

- Accessibility
  - Weights available: Yes -- HuggingFace at facebook/ShapeR (auto-downloaded). Includes flow matching model, VAE, configs, DINOv2 weights.
  - Inference code available: Yes -- `infer_shape.py` with complete pipeline
  - Training code available: No
  - License: CC-BY-NC 4.0 (some components Apache 2.0)

- Efficiency
  - Typical inference runtime: Unknown (depends on config: quality=50 steps, balance=25, speed=10)
  - GPU memory: Unknown (uses bfloat16 + torch.compile)
  - Sampling steps: 10 (speed), 25 (balance/recommended), or 50 (quality) via midpoint ODE solver. Optional Flux-style time shifting.

- Strengths
  - Handles casual in-the-wild captures from Aria glasses, not studio settings
  - Multi-modal conditioning (point cloud + multi-view images + text) with graceful degradation via condition dropping
  - Metric-scale 3D reconstruction (preserves real-world dimensions)
  - Variable token count in VAE enables adaptive detail
  - Flow matching (rectified flow) provides stable, efficient generation
  - Publicly available weights on HuggingFace

- Limitations
  - Geometry only -- no texture or material reconstruction
  - Requires preprocessed data (Aria MPS pipeline + 3D object detection) -- not end-to-end
  - Training code not released
  - Non-commercial license (CC-BY-NC 4.0)
  - Depends on legacy torchsparse fork
  - Designed specifically for Aria glasses data format (FISHEYE624)
  - UDF-based mesh extraction may produce floating geometry artifacts

- Distillation Suitability
  - Teacher quality potential: High -- rich multi-modal conditioning, metric-scale 3D meshes, flow matching
  - Multi-view compatibility: High -- natively multi-view (4-16 views), camera-aware via Plucker coordinates, flexible view selection
  - Latent accessibility: High -- clean VecSet latent space with separate VAE; latents explicitly accessible; DiagonalGaussianDistribution
  - Reproducibility: Medium -- inference code and weights available; no training code; depends on Aria-specific data format
  - Overall suitability score (1-5): 4

# TRELLIS

- Basic Information
  - Paper: "Structured 3D Latents for Scalable and Versatile 3D Generation" (arXiv:2412.01506)
  - Repo: https://github.com/microsoft/TRELLIS
  - Year: 2024
  - Organization: Microsoft
  - Task framing: Conditional 3D asset generation (image-to-3D and text-to-3D) via two-stage latent diffusion with rectified flow matching
  - Output type: 3D Gaussians, Radiance Fields, Meshes (all from a single shared latent)

- Input / Output
  - Inputs
    - Modalities: Single image (RGBA/RGB) or text prompt
    - Required preprocessing: Background removal (rembg/u2net), crop to object bbox with 1.2x padding, resize to 518x518, alpha-premultiplied RGB, DINOv2 ImageNet normalization
    - Input resolution: 518x518 (matching DINOv2 ViT-L/14)
    - Conditioning method: DINOv2 ViT-L/14 with registers patch tokens (pre-norm, layer-normalized) as cross-attention conditioning to DiT blocks. Text conditioning via separate model. CFG with p_uncond=0.1.
  - Outputs
    - Representations: 3D Gaussians (32 per voxel), Radiance Fields (Strivec tri-vector decomposition), Meshes (FlexiCubes at 4x upsampled resolution with vertex colors)
    - Texture / material support: RGB color (SH degree 0 for Gaussians). GLB with baked texture (default 1024). No PBR.
    - Post-processing required: GLB extraction via mesh simplification (95% triangle reduction) and texture baking from Gaussian splatting onto mesh UV

- Core Architecture
  - Internal representation: Structured Latent (SLAT) -- sparse voxel grid with per-voxel 8-channel latent features at 64^3, stored as SparseTensors. Occupancy from separate Sparse Structure (SS).
  - Backbone: Rectified Flow Transformer (DiT-style) with Modulated Sparse Transformer Cross Blocks, AdaLN for timestep, cross-attention for image/text. SS flow model: dense DiT with patchify/unpatchify. SLAT flow model: sparse convolution IO blocks + sparse transformer core.
  - Latent / VAE
    - VAE present: Yes, two VAEs: (1) SS VAE (3D Conv encoder/decoder for binary occupancy), (2) SLAT VAE (sparse transformer encoder + multiple decoders for Gaussians/RF/Mesh)
    - Latent structure: SS VAE: dense 3D grid, 8-channel at 16^3 (4x downsampled from 64^3, channels [32,128,512]). SLAT VAE: sparse 8-channel per voxel at resolution 64, Swin-style windowed attention (window size 8), 12 transformer blocks, 768 channels.
    - What the VAE encodes: SS VAE: binary 3D occupancy. SLAT VAE encoder: per-voxel DINOv2 features (1024-dim, aggregated from 150 multiview renders) to 8-dim latent. Decoders output Gaussians, radiance fields, or meshes.
  - Pipeline structure
    - Stages: (1) Generate sparse structure latent via dense flow model -> decode to binary occupancy -> threshold at 0. (2) Generate SLAT features on occupied voxels via sparse flow model -> denormalize -> decode to Gaussians/RF/Mesh via frozen decoders.
    - Key modules: TimestepEmbedder, AbsolutePositionEmbedder, ModulatedTransformerCrossBlock (dense), ModulatedSparseTransformerCrossBlock (sparse), SparseResBlock3d (IO), FlowEulerSampler/FlowEulerGuidanceIntervalSampler, SparseConv3d (spconv), Swin-style windowed sparse attention

- Multiview Support
  - Native multiview support: Partial -- multi-image conditioning as tuning-free inference technique (not specially trained). Two modes: 'stochastic' (cycles views across steps) and 'multidiffusion' (averages predictions from all views).
  - Multi-view aggregation: Stochastic: round-robin view assignment. Multidiffusion: average velocity predictions. Injected at inference via `inject_sampler_multi_image` context manager.
  - View count supported: Arbitrary (warning if num_images > num_steps in stochastic mode)
  - View consistency mechanism: No explicit mechanism. During data prep, DINOv2 features from 150 multiview renders are aggregated into voxels, providing implicit multiview supervision for VAE training.

- Training Setup
  - Training datasets: TRELLIS-500K: 500,777 3D assets from Objaverse(XL) sketchfab (168K) + github (312K), ABO (4.5K), 3D-FUTURE (9.5K), HSSD (6.7K). Filtered by aesthetic score.
  - Dataset scale: ~500K training objects, ~495K with text captions
  - Supervision signals: SS VAE: binary occupancy reconstruction. SLAT VAE (Gaussian): rendered image reconstruction. Flow models: velocity prediction (v-prediction) MSE.
  - Losses: SS VAE: Dice + KL (lambda=0.001). SLAT VAE Gaussian: L1 + SSIM (0.2) + LPIPS (0.2) + KL (1e-6) + volume reg (10000) + opacity reg (0.001). Flow models: MSE velocity. Logit-normal timestep schedule (mean=1.0, std=1.0). CFG dropout p=0.1.
  - Training code available: Yes -- full training framework with `train.py`, configs for all variants, distributed training support.

- Strengths
  - Unified SLAT representation decodes to multiple formats (Gaussians, radiance fields, meshes) from single generation
  - Large-scale training on 500K curated 3D assets with models up to 2B parameters
  - Complete codebase with both training and inference code
  - Modular: separate VAEs and flow models allow independent training
  - Flexible conditioning (image and text)
  - MIT license enables broad use including distillation
  - Sparse representation is memory-efficient (up to 32K voxels per object)

- Limitations
  - Multi-view conditioning is tuning-free/heuristic, not trained for multi-view input
  - Text-to-3D acknowledged as "less creative and detailed due to data limitations"
  - No PBR material support (only RGB color, SH degree 0)
  - No evaluation scripts in repo
  - Heavy dependency stack (spconv, diffoctreerast, kaolin, nvdiffrast, flash-attn, custom CUDA extensions)
  - Linux-only
